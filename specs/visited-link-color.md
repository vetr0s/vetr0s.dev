# Remove the visited link color

## Goal
Visited links currently render pink (`#f690ff`) against unvisited links in blue (`#89a6ff`). The owner finds the pink ugly. This change removes the visited-link rule so every link uses the one blue. The `a` rule also matches visited links and author styles beat the browser default, so deleting `a:visited` gives visited links the same blue.

## Acceptance criteria
1. `static/style.css` and `docs/style.css` contain no `:visited` rule, and `a { color: #89a6ff; }` is unchanged in both.
2. After `swag build`, `static/style.css` and `docs/style.css` are byte-identical (`cmp` exits 0).
3. In a real browser, a visited link and an unvisited link render in the same blue. JS `getComputedStyle` cannot verify this because browsers hide visited state from scripts, so the check is a screenshot of a page with one visited and one unvisited link.
4. Any other change under `docs/` after the rebuild is listed in the hand-off. Unrelated generated changes are reported, not reverted or hidden.

## Files to touch
`static/style.css`: delete line 15, `a:visited { color: #f690ff; }`.
`docs/style.css`: regenerated by `swag build`. Not edited by hand. Commit it with the source change per AGENTS.md.

## Test plan
The repo has no test framework, lint, or typecheck. No tests are added to the repo.
1. Criterion 1: run `grep -n visited static/style.css docs/style.css` and expect no output. Run `grep -n '^a { color: #89a6ff; }' static/style.css docs/style.css` and expect one match per file.
2. Criterion 2: run `swag build`, then `cmp static/style.css docs/style.css` and expect exit 0.
3. Criterion 3: open a built page in a browser, visit one link, return, and screenshot. Both links must show `#89a6ff`. Manual check.
4. Criterion 4: run `git status --short docs/` and `git diff --stat docs/` after the build. Expect only `docs/style.css`. Report anything else.

## Out of scope
- A new, subtler visited color. The narrower reading of "less annoying or remove it" is removal.
- Hover, focus, or active link styles.
- CSS variables or any other restyling of the theme.
- Adding a test framework or a committed test script.
- Changes to swag or its layouts.
